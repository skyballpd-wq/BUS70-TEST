# 비공개 원장 자동 스냅샷 준비

이 폴더는 **별도 Apps Script 프로젝트**용이다. 운영 웹앱 프로젝트나 공개 HTML에 붙이지 않는다. 코드는 기본 비활성 상태이며 저장소 반영만으로 백업이 시작되지 않는다.

## 동작 범위

- 15분 시간 트리거가 변경을 확인한다. 변경이 있으면 성공한 이전 복사 후 최소 1시간 간격으로 전체 원장을 복사하고, 변경이 없어도 24시간 경과 시 복사한다. 실행 시각과 재시도는 지연될 수 있다.
- Script/API 쓰기는 시트 `onEdit` 트리거를 발생시키지 않으므로 별도 시간 트리거를 사용한다. Drive 수정시각은 변경 확인용이며 변경 이벤트 원장이나 실시간 무손실 복제는 아니다.
- 개인 My Drive의 소유자만 접근하는 원장과 백업 폴더만 허용한다. 소유자·공유 링크·개별 편집자/조회자·휴지통 상태를 매번 검사한다. 공유 드라이브와 타인 소유 항목은 지원하지 않는다. 기존 공유 권한은 바꾸지 않는다.
- 사본이 올바른 폴더 안에 있고 비공개이며 Sheets로 열리는지 검증한 후 성공 시각을 저장한다. 검증 전 생성된 사본은 `pendingCopy`로 남기고 다음 실행에서 같은 사본을 재검증한다. 검증 실패마다 복사본을 추가하지 않는다. 이 검증은 전체 셀 일치나 실제 복원 시험을 대신하지 않는다.
- 실패 시 15/30/60/120/240분 후 재시도한다. 원본 데이터·이메일·비밀 키·서비스 예외 원문을 로그에 출력하지 않는다. 보안 점검 실패 시에도 원본은 수정하지 않는다.
- 삭제 기능은 없다. 현재 원장 ID로 만든 사본이 240개면 추가 생성을 중지하고 `CAPACITY_REVIEW_REQUIRED`를 기록한다. 이전 사본의 외부 보관·정리와 보존정책은 별도로 확인해야 한다. 240개가 찰 때까지 무인 보장된다는 의미는 아니다.
- 백업 프로젝트의 잠금은 이 프로젝트 중복 실행만 막는다. 운영 저장을 지연시키지 않으며, 여러 원장 시트의 저장을 하나의 거래로 묶는 일관성은 보장하지 않는다. 복사 중 변경은 다음 스냅샷 대상에 남긴다.

## 활성화 절차

1. 소유자 Google 계정으로 별도 프로젝트를 만든다. `Code.gs`와 이 폴더의 `appsscript.json`만 넣는다. 프로젝트 공유와 웹앱/API 실행 배포는 하지 않는다.
2. 프로젝트 설정 → 스크립트 속성에 `BUS70_BACKUP_SOURCE_ID`, `BUS70_BACKUP_FOLDER_ID`, `BUS70_BACKUP_OWNER_EMAIL`을 넣는다. 실제 값을 공개 GitHub에 쓰지 않는다. `BUS70_BACKUP_ENABLED`는 먼저 `false`로 설정한다.
3. `bus70BackupPreflight`를 실행하고 필요한 Google 권한을 소유자가 검토한다. Drive 복사에 필요한 권한은 넓은 Drive 범위이므로 기존 웹앱과 프로젝트를 분리한다. 이메일 발송·외부 URL 전송 권한은 없다.
4. 속성 `BUS70_BACKUP_ENABLED`를 `true`로 바꾸고 `bus70BackupTick`을 수동 실행한다. `snapshot-created` 후 비공개 상태·사본 위치와 중요 셀을 원본에 대조한다. 별도 임시 문서에 복원하여 운행일, 배차, 정비, 계정 접근 제한과 실제 시각 보존을 검증한다. 운영 원장을 덮어써서 시험하지 않는다.
5. `bus70BackupInstall`을 실행한다. 같은 계정의 동일 함수 트리거는 중복 생성하지 않는다. 다른 계정으로 설치하지 않는다. 트리거 목록의 함수명과 15분 간격을 확인하고 실패 알림을 설정한다.
6. 다음 자동 실행 후 `bus70BackupStatus`의 성공 시각 및 사본을 확인해야 **자동 백업 활성화**로 기록한다. 상태는 비공개 프로젝트 속성에 보관하며 소장 앱 대시보드에는 아직 연결하지 않는다.
7. 중지 시 `bus70BackupDisable`을 실행한다. 사본과 트리거는 보존되며 비활성 트리거는 즉시 종료한다.

## 남은 실시간 백업 단계

현재 운영 저장 함수와 관리자의 직접 시트 수정은 경로가 다르다. 모든 변경에 고유 이벤트 ID와 저장 결과를 기록하는 비공개 변경 원장, 실패 재전송, 중복 제거, 주기 전체 복원 검증을 먼저 구현해야 한다. 해당 구현과 운영 배포 전에는 이 스냅샷을 실시간 백업으로 안내하지 않는다. 공개 GitHub에는 코드만 보관한다.
