# 정비소 차량 복귀·점검 공유

정비소가 점검 대상 차량의 복귀를 기다리며 수동으로 기사를 찾던 업무를, 전체 노선 차량 현황과 차량별 점검 안내로 연결한다. 웹 v89.5 후보이며 아직 운영 배포 전이다. Android91의 기존 공지 음성 연결을 사용하므로 네이티브 코드 변경은 없다.

## 화면과 업무 흐름

1. Center 로그인 첫 화면 또는 Master/Major의 ‘차량·정비’에서 5·23·70번 차량을 본다. 전체 노선/개별 노선/점검 대상 필터를 제공한다.
2. 차량 카드에서 오늘 확정 배차 기사, 최근 정류장, 노선 진행, 차고지 방면 남은 정류장, 미완료 점검 요청을 확인한다. 미배차 차량도 등록 노선과 정비 상태는 표시한다.
3. 점검 대상이 차고지에서 2정류장 이내일 때 상단에 접근 차량을 강조한다. 공급 정보는 정류장 위치 참고이며 실제 도착·주차·입고 완료가 아니다.
4. Center/Master가 기존 미완료 점검 건과 오늘 배차 기사를 선택해 ‘복귀 후 점검’ 또는 ‘긴급 연락 요청’을 미리보고 발송한다. 점검 건이 없으면 기존 정비 요청 등록 화면으로 이동한다. 이때 이전 대차 선택·순차를 재사용하지 않는다.
5. 기사는 기존 공지함에서 수신한다. 수신/음성 재생/기사 직접 확인은 각각 기록한다. 실제 입고와 정비 완료는 기존 정비 처리 화면에서 Center/Master가 별도로 기록한다. 완료일과 운행 가능일을 별도로 표시한다.
6. 소장은 전체 현황·요청·수신 결과를 조회한다. Center의 점검 안내 권한을 일반 전체 공지 발송 권한으로 확대하지 않는다.

## 데이터와 정확도

- 오늘은 기존 한국시간 운행일(03:30 경계)로 판정한다. 과거·미래 배차를 오늘 기사로 대신하지 않는다. 동일 차량 복수 배차는 선택 목록으로 구분하고 발송 대상을 직접 확인한다.
- 차고지 복귀는 유일한 회차점 이후 순번과 명시된 차고지 종점으로 판단한다. 회차·종점이 불명확하면 남은 정류장을 추정하지 않는다. 출발측 차고지를 복귀로 취급하지 않는다.
- 앱 GPS는 당일 차량·기사·배차·순차·탕이 실제 진행 운행일지와 일치하고 정확도 60m 이내/45초 이내일 때만 쓴다. 완료된 탕 이후 휴대폰 이동은 차량 이동으로 사용하지 않는다.
- 경기버스정보는 기존 노선별 공유 조회·45초 캐시·요청 제한 대기를 재사용한다. 차량마다 API를 호출하지 않는다. 공급자가 위치 측정 시각을 제공하지 않으므로 ‘조회 시각’을 명시한다. 정류장 ID와 순번이 맞고 차량 식별이 유일해야 한다. 조회 60초가 지나면 진행·접근 표시를 해제한다.
- 실제 진행 탕의 운행일지에 차고지 도착 예정이 있으면 ‘시간표 기준’으로 표시한다. 이동 속도로 새 ETA를 만들지 않는다. 마지막 도착 기록을 현재 주차 증거로 사용하지 않는다.
- 전면 화면에서 45초마다 갱신한다. 앱이 닫혔거나 로그아웃한 기사에게 푸시하지 않는다. 미수신은 별도 연락이 필요한 상태다. 일반 점검 요청은 화면 안내, 긴급 요청만 명시적으로 음성을 켠 기사에게 자동 재생한다. 운전 중 조작 제한과 안전 음성 우선순위는 기존 공지 정책을 유지한다.

## 저장 및 권한

- 신규 `정비호출DB`: callId, requestHash, serviceDate, vehicleId, maintId, dispatchId, driverId, createdAt, createdBy, mode, message, expiresAt, status. 조회로 생성하지 않으며 최초 실제 발송 때 생성한다.
- `공지수신DB`의 별도 receivedAt/playedAt/acknowledgedAt을 재사용한다. 발송·취소는 `변경이력DB`에 기록한다. 감사 기록 실패 건은 전달하지 않는다.
- 대상 미리보기의 revision을 저장 직전에 대조한다. 같은 요청 ID 재시도는 중복 발송하지 않는다. 동일 점검 건·배차에 활성 안내가 있으면 새 발송을 거부한다.
- 수신 조회마다 현재 배차와 차량 연결을 재검증한다. 대차/기사 변경 시 이전 안내를 새 기사에게 자동 전환하지 않는다. 실제 입고 또는 완료가 기록되면 전달을 중단한다. 취소·12시간 또는 운행일 종료 중 빠른 시점에 만료된다.
- 호출은 입고시간·출고시간·정비상태·차량상태·배차·실제 운행기록을 쓰지 않는다. 위치 계산도 이 기록들을 쓰지 않는다. ‘정비중’ 선택은 기존 업무상 실제 입고 기록을 생성하므로 담당자가 실제 입고를 확인하고 처리한다.
- 기사에게 다른 차량의 정비 현황을 반환하지 않는다. 정비 현황 응답에는 사번·계정·연락처·원시 GPS 좌표를 포함하지 않는다. 브라우저에는 응답을 영구 저장하지 않고 로그아웃 때 비운다.

## 검증과 배포

- `tests/maintenance-board.test.js`: 역할/조회 전용/당일 배차/공유 조회/오래된 위치/회차·종점/실제 운행 대조/입고 후 이동 배제/대상 변경/중복 방지/감사 실패/별도 수신/취소/만료.
- `tests/maintenance-board-client.test.js`: 45초 전면 조회/미리보기 무효화/유실 응답 재시도 ID/통신 장애 시 위치·발송 비활성/로그아웃/이전 세션 응답 차단.
- `tests/maintenance-board.browser.cjs`: Chromium/WebKit에서 320/412/1180px, 필터·미리보기·재시도·수신 상태·취소·장애·권한·가로 넘침 검사. 실행 결과는 WORK_STATUS에 별도 기록한다.
- 신규 `MaintenanceDispatch.gs`, 기존 `ManagerDispatch.gs`의 네 operation 및 특정 정비건 조회 연결, `OperationsNotice.gs`의 점검 안내 feed 연결을 함께 배포해야 한다. 기존 운영 Apps Script는 저장소와 차이가 있으므로 전체 덮어쓰지 않고 최신 원본에 부분 적용 후 재조회한다.
- 실제 차량·기사 시험 호출, 실제 정비 상태 변경, 운영 DB 신규 시트 생성은 수행하지 않는다. 실차 수신·음성·정비소 모니터 확인은 별도 검증 사항이다.
