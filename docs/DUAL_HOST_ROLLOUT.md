# 같은 플랫폼을 두 주소에서 운영하는 단계별 전환

## 현재 상태와 목표

기존 웹주소 https://skyballpd-wq.github.io/BUS70-TEST/ 를 유지한다.
Cloudflare 쪽은 같은 main 커밋의 정적 웹앱을 별도 Pages 프로젝트로 배포하고 같은 기존 API/원장을 사용하도록 준비한다. 현재 Cloudflare 계정 로그인·Pages 생성·도메인 연결은 완료 확인 전이다. 이 문서는 설정 절차이며 활성화 증거가 아니다.

sosin.win의 기존 서비스/DNS를 확인한 뒤 충돌이 적은 bus.sosin.win을 먼저 연결하는 안이다. 루트 도메인 연결은 기존 사용처를 확인한 다음 결정한다. GitHub Pages의 Custom domain/CNAME 설정은 변경하지 않는다. 기존 주소가 새 주소로 강제 이동하지 않아야 한다.

## 배포 설정

1. Cloudflare Workers & Pages에서 Pages 프로젝트를 만들고 이 저장소만 GitHub 연결 대상으로 선택한다.
2. Production branch는 main, framework preset은 None, build command는 `node scripts/build-static-site.js`, output directory는 `.pages-dist`로 지정한다. Node 22로 검증한다.
3. 먼저 pages.dev 주소에서 HTTPS, 로그인/권한, 배차 조회, GPS 권한, 수동·자동 기록, 미전송 재시도, 소장 화면을 확인한다.
4. Custom domains > Set up a domain에서 사용할 호스트를 등록한 뒤 안내된 DNS 연결을 확인한다. DNS CNAME만 먼저 만드는 방식은 피한다.
5. 두 호스트에서 동일 배포 커밋, 핵심 파일 SHA-256, 동일 API와 원장, 권한 거부 응답을 확인한다. 운영 기록을 만들지 않는 합성 테스트부터 진행한다.
6. 제한된 현장 검증 후 일반 사용자에게 안내한다. 문제가 있으면 기존 주소를 계속 사용하며 새 호스트만 직전 검증 버전으로 되돌린다.

빌더는 서비스워커 정적 목록의 앱 파일만 포함한다. 앱과 API 주소를 바꾸지 않으며 서버 소스·시험·문서·Android 소스는 배포 묶음에서 제외한다. `asset-digests.json`으로 파일별 일치를 확인할 수 있다. API 응답과 개인정보를 정적 캐시로 만들지 않는다.

## 동일한 데이터와 기기별 차이

| 항목 | 두 주소에서 유지할 동작 | 확인할 차이 |
|---|---|---|
| 배차·정비·운행 기록 | 같은 기존 API와 비공개 원장 | 별도 복제 원장에 이중 쓰기하지 않음 |
| 로그인·권한 | 같은 계정/역할 검증 | 로그인 세션은 브라우저 origin별로 별도 |
| GPS·음성 | 같은 웹 로직 | 새 주소에서 위치·음성 권한 재확인 |
| 미전송 운행 기록 | 기존 멱등성·재시도 보존 | 저장 큐는 origin별이므로 기존 큐 저장 완료 후 전환 |
| 실시간 차량 정보 | 서버의 노선별 공용 응답 재사용 | 창을 두 개 열어 같은 차량 GPS를 동시에 전송하지 않음 |
| 앱 설치/PWA | 같은 버전 웹앱 | 기존 홈 화면 아이콘과 새 주소 아이콘은 별개 |
| Android 네이티브 | 기존 APK/주소 계속 사용 | 새 origin의 브리지 허용·백그라운드 GPS는 별도 코드/서명 검증 필요 |

도메인 연결만으로 브라우저의 백그라운드 GPS 제한, API 쿼터, 서버 처리량이 개선되지는 않는다. 이번 단계는 웹 정적 호스팅 준비다. Android96 네이티브 변경과 신규 APK 빌드를 완료했다고 해석하지 않는다.

## 백업의 역할과 다음 단계

- GitHub: 공개 가능한 소스·테스트·변경 이력. 커밋/푸시 시 보관하며 실제 기사 개인정보·운행 원장은 업로드하지 않는다.
- Google Sheets: 현재 업무의 원장. 정상 저장된 변경은 두 주소에서 같은 서버로 읽는다. 원장 자체를 독립 백업으로 간주하지 않는다.
- Google Drive: 비공개 시점별 복사본. 수동 스냅샷과 자동 백업을 구분한다.
- 후속 자동화: 저장 이벤트의 고유 ID/시각/재시도 상태를 보관하고 변경분 백업 및 정기 전체 스냅샷을 조합한다. 백업 성공시각·실패 재시도·보존기간·복원 시험을 확인한 뒤 활성화 완료로 기록한다. 잦은 전체 시트 복사 방식은 용량·실행 한도에 불리하다.
- 현재 수동 복사본은 확보했으나 자동 백업 트리거/변경분 동기화는 아직 활성화하지 않았다. 실시간 무손실 복제라고 표현하지 않는다.
