# 공지·정비 회신 적용안

앱을 열어 둔 로그인 기사에게 전달하는 공지다. 웹89.4와 Apps Script 서버78에 반영했으며 Android91 설치파일을 제공한다. 카카오톡·문자 발송, 백그라운드 푸시, 미로그인 기사 도달을 포함하지 않는다.

## 사용자 동작

- 소장·마스터: 기사 공지 → 전체/당일 배차/노선/개별 선택 → 제목·내용 → 대상 미리보기 → 확인 체크 → 보내기. 노선 공지는 기본 소속 대신 현재 운행일의 확정 배차를 사용한다. 미리보기 후 배차가 바뀌면 다시 확인한다.
- 기사: 운행 화면 한 줄 표시, 아래 공지·정비 회신함에서 상세 확인. 음성은 로그인 세션마다 직접 켜며 긴급 공지만 자동 재생한다. 안전 안내가 우선한다. 수신/음성 재생/직접 확인은 각각 기록한다.
- 정비소·마스터: 기존 요청의 ‘정비 요청 접수 확인’. 기존 수리 결과·진행 상태를 저장하면 관련 기사 공지함에서 회신을 확인한다. 접수 확인은 실제 입고·수리 완료·운행 허가를 의미하지 않는다.

## 저장·권한

- 운영공지DB: 요청ID·내용 해시·작성자/시각·운행일·대상 종류/고정 수신자ID·제목/내용·우선순위·만료·상태.
- 공지수신DB: 공지/기사 조합별 고유ID와 수신/재생/직접확인 시각. 클라이언트가 제출한 임의 시각을 쓰지 않는다. 재생은 기기 완료 보고이며 기사가 실제로 들었다는 보장은 아니다.
- 정비DB: 선택적 접수확인자·접수확인시각. 접수 확인은 기존 정비·차량 상태나 입출고 시간을 바꾸지 않는다. 정비이력DB·변경이력DB와 연결한다.
- 서버가 인증 역할과 수신 대상 여부를 검증한다. 새 공지·취소는 감사 기록을 남긴다. 감사 실패 시 새 공지가 전달되지 않는다. 같은 발송 ID의 재요청은 중복을 만들지 않으며 내용을 바꾼 재사용은 거절한다.
- 대상 목록은 발송 시 고정된다. 발송 뒤 배차가 변경되면 기존 공지를 취소하고 새 대상을 확인해 다시 보낸다. 지정 만료 또는 다음 운행일 경계 03:30 중 빠른 시점에 끝난다.
- 정비 회신은 원 기사·원 신고자·당일 해당 차량 배차기사에 한하며 최근 7일만 표시한다. 실제 정비 이력 내용을 전달하므로 정비 담당자는 기사에게 공유할 내용만 기록해야 한다.

## 동작 한계와 남은 검증

- 전면 앱에서 45초 간격으로 조회한다. 70초 이상 동기화가 없으면 오래된 상태를 표시하고 자동 음성을 중지한다. 취소는 다음 정상 조회에서 반영되며 이미 들은 음성을 되돌릴 수 없다.
- 운행 중 속도가 있거나 위치가 불명확하면 수동 확인/음성 설정을 막는다. GPS 정지는 안전한 주차를 증명하지 않으므로 실제 조작은 안전하게 정차한 뒤 한다.
- Android 91의 새 전면 음성 연결이 필요하다. 기존 APK의 WebView 음성 지원은 보장하지 않는다. 브라우저는 지원 시 자체 음성 엔진을 사용한다. 수신 기록 재시도는 현재 세션 메모리이며 로그아웃 후 유지되지 않는다.
- 합성 서버/클라이언트 상태 검사, 관련 Node 회귀, Chromium/WebKit 레이아웃·공지 동작, Android 단위 검사·서명 빌드·기존 에뮬레이터 검사 통과. 웹 배포 파일 일치와 서버78 배포·권한 없는 요청 차단을 확인했다. 실제 모바일 계정별 공지 전달과 TTS 청취·운행 중 음성/수신은 미검증이며 실제 기사에게 시험 공지를 보내지 않았다.
- 사용자가 게시·배포를 승인하여 PR70을 병합했다. 서버 최신 원본에 부분 반영 후 읽기 전용 검증·저장본 재조회·임시 진단 제거를 완료했다. 정비 접수·공지 발송·수신시트 기록을 시험 목적으로 운영 원장에 만들지 않았다. Android 음성 연결은 91 설치 후 사용하며 기사 공지함에서 로그인 세션마다 음성을 켠다.
