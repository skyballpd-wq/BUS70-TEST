# BUS70 기사 Android 연결 모듈

이 모듈은 기존 BUS70 웹화면을 WebView로 사용하면서 휴대폰 네이티브 기능만 연결한다.

구현 범위:

- 확정 배차의 탕별 일정을 휴대폰 캘린더에 등록
- `AlarmManager.setExactAndAllowWhileIdle` 기반 정확한 알람
- 휴대폰 기본 알람음 또는 기사가 고른 내장 알람음
- 화면 잠금 상태 알림 및 한국어 TTS
- 기사 승인 후 화면 잠금 상태에서도 동작하는 GPS 전경 서비스
- 로그인 기사·확정 배차·배정 차량 일치 검증 후에만 GPS 추적 시작
- 노선별 정류장 좌표를 이용한 이전·다음 정류장, 진행률, 현재속도 표시
- 같은 노선 앞차·내 차량·뒷차의 최신 위치와 예상 배차간격 공유
- 검증된 노선 기준점 이탈·진입에 따른 발차·회차·도착 자동 기록
- 재부팅·시간대 변경·정확한 알람 권한 변경 후 예약 복원
- 03:30 운행일과 자정 이후 운행 처리

## 빌드

Android Studio에서 `android` 폴더를 열고 설치된 Android SDK 35로 빌드한다. 테스트 APK는 `app` 모듈의 debug 변형을 사용한다.

저장소에 반영하면 `.github/workflows/android-apk.yml`이 시험용 APK를 자동 생성한다. GitHub Actions 실행 결과의 `BUS70-driver-test-apk`에서 설치파일을 받을 수 있다.

## 실제 휴대폰 필수 검증

1. 앱 설치 후 기사 계정으로 로그인한다.
2. 오늘 확정 배차를 조회한다.
3. `알림 권한 허용`을 눌러 캘린더·알림·정확한 알람을 승인한다.
4. 휴대폰 기본 알람음과 기사 선택 내장음을 각각 시험한다.
5. 5분 이내 시험 스케줄을 등록하고 앱을 최근 앱 화면에서 닫는다.
6. 화면을 잠근 상태에서 알람음·잠금화면 알림·TTS를 확인한다.
7. 배차시간 변경 후 이전 알람이 울리지 않고 새 알람만 울리는지 확인한다.
8. 휴대폰 재부팅 후 예약 알람이 복원되는지 확인한다.
9. 23시 이후 출발 및 익일 00시 이후 도착 일정이 같은 운행일로 등록되는지 확인한다.
10. 오늘 확정 배차에 기사·순차·차량이 모두 연결되었는지 확인한다.
11. 노선별 `노선_<노선번호>_정류장DB`에 순서·정류장명·위도·경도가 등록되었는지 확인한다.
12. 오늘 배차에서 `GPS 자동기록·실시간 공유 시작`을 누른다.
13. 위치 권한을 허용하고 상단의 지속 알림이 표시되는지 확인한 뒤 화면을 잠근다.
14. 발차지 이탈, 회차지 진입, 도착지 진입 후 앱을 다시 열어 실제시각·GPS 자동 표시와 완료 탕 회색 처리를 확인한다.
15. 같은 노선 앞·뒤 순차의 테스트 앱에서도 위치 공유를 켜고 차량 위치·배차간격이 15초 안팎으로 갱신되는지 확인한다.

사용자가 Android 설정에서 앱을 강제 종료하면 운영체제 정책에 따라 예약 실행이 중단될 수 있다.
위치 자동 기록도 사용자가 지속 알림의 `추적 중지`를 누르거나 앱을 강제 종료하면 중단된다. 이동 경로 이력은 저장하지 않는다. 발차·회차·도착 이벤트는 운행일지에 보존하며, 차량의 최신 위치 스냅샷만 서버 캐시에 두고 10분 후 자동 삭제한다.

## v61 위치 판정 보완

- 중복·오래된·부정확한 GPS 수신을 제외하고 운행일이 달라지면 추적을 중지합니다.
- 중간에 앱을 켜면 실제 진행 중인 기록을 우선하고, 기록이 없으면 현재 시각에 해당하는 예정 탕을 선택합니다. 지난 탕의 기록은 생성하지 않습니다.
- 필요한 회차 기준점이 미등록이면 도착을 자동으로 확정하지 않습니다. 발차·회차·도착 이벤트는 관측 시각을 서버에 전달합니다.
- 이번 소스 변경은 새 APK 설치가 필요합니다. 웹 업데이트만으로 설치된 네이티브 서비스가 교체되지는 않습니다.
